# Discord-бот «Слив склада»

## Установка

Пакет рассчитан на pnpm-монорепо (как в корне репозитория). Скопируйте
`lib/log-analyzer` и `apps/discord-bot` в соответствующие места существующего
воркспейса — `pnpm-workspace.yaml` уже включает `apps/*` и `lib/*`, отдельных
правок workspace-конфига не требуется, если у вас уже есть паттерн `apps/*`
(если нет — добавьте `apps/*` в список `packages` в `pnpm-workspace.yaml`).

```bash
pnpm install
cp apps/discord-bot/.env.example apps/discord-bot/.env
# заполните DISCORD_TOKEN, DISCORD_CLIENT_ID, LOGS_CATEGORY_ID (см. ниже)
```

## Discord-приложение

1. https://discord.com/developers/applications → New Application.
2. Bot → Reset Token → скопировать в `DISCORD_TOKEN`.
3. Bot → Privileged Gateway Intents → включить **Message Content Intent**
   (без него бот не сможет читать текстовые логи, вставленные в чат).
4. OAuth2 → URL Generator → scopes: `bot`, `applications.commands`; права:
   `Manage Channels`, `View Channels`, `Send Messages`, `Attach Files`,
   `Read Message History`, `Manage Messages` — пригласить бота на сервер по
   сгенерированной ссылке.
5. Создать на сервере категорию «Логи», скопировать её ID (Настройки Discord →
   Расширенные → Режим разработчика, затем ПКМ по категории → «Копировать ID»)
   в `LOGS_CATEGORY_ID`.

## Регистрация команды

```bash
pnpm --filter @workspace/discord-bot run deploy-commands
```

Если задать `DISCORD_GUILD_ID` в `.env` — команда появится на конкретном
сервере мгновенно (удобно для разработки). Без него регистрация глобальная и
может занять до часа.

## Запуск

```bash
pnpm --filter @workspace/discord-bot run dev     # разработка, автоперезапуск
pnpm --filter @workspace/discord-bot run build   # сборка в dist/
pnpm --filter @workspace/discord-bot run start   # прод-запуск собранного бандла
```

## Как это работает

1. `/sliv` — проверяет, что у пользователя нет активной сессии, создаёт
   приватный канал в категории `LOGS_CATEGORY_ID`, видимый только автору и
   боту.
2. В канале запускается визард (`src/wizard.ts`): выбор фракции → лог склада →
   логи размещений (можно несколько сообщений/файлов) → состав фракции
   (опционально) → фамилия админа.
3. Каждое текстовое сообщение или прикреплённый файл от автора сессии
   считывается и добавляется в накопитель; кнопка «Готово» завершает шаг.
4. По завершении сбора запускается `runAnalysis` из `@workspace/log-analyzer`
   и результат отправляется в канал файлом `report_<фракция>_<timestamp>.txt`.
5. Канал сессии **не удаляется** — остаётся в категории как архив. Слот
   «активная сессия» пользователя освобождается сразу после завершения
   обработки (успешного или с ошибкой), так что новую сессию можно запускать
   сразу.

## Учёт каптов (capt-tracker)

Отдельная от `/sliv` функция — живёт в `src/captTracker/`, `src/commands/captAdmin.ts`.

1. Бот читает канал-источник (сервер `1546926301699514411`, канал
   `1552702236117696593`), куда переносятся забивы каптов из офф-дискорда.
   На каждое новое сообщение (`src/captTracker/listener.ts`) парсер
   (`parser.ts`) вытаскивает поля «Атака:»/«Защита:»/«Дата и время:» и т. д.
   Последующее редактирование этого же сообщения ботом-источником (когда
   добавляется «Результат:»/«Статистика:») **игнорируется** — считается
   только сам факт забива, как и было указано в ТЗ.
2. День считается по дате из поля «Дата и время:» самого сообщения (не по
   часам бота), в формате `ДД.ММ.ГГГГ` → ключ `ГГГГ-ММ-ДД`. Счётчики за день
   хранятся в `src/captTracker/store.ts` (JSON-файл, путь — `CAPT_DATA_FILE`,
   по умолчанию `./data/capt-store.json`), переживают перезапуск бота.
3. По каждому новому забиву в оба канала (`DESTINATIONS` в `config.ts`) уходит
   сообщение со сводкой за день по всем фракциям и кнопкой «Отменить капт».
   Если у какой-то фракции атак или защит за день больше 3 (правило 1.2,
   `DAILY_ATTACK_DEFENSE_LIMIT` в `config.ts`) — добавляется блок с
   упоминанием роли этого сервера и списком нарушений.
4. Кнопка «Отменить капт» откатывает ровно одну атаку и одну защиту
   участвовавших фракций и делает кнопку неактивной. Нажать её могут:
   создатель бота, добавленные помощники, либо участник с ролью,
   привязанной к серверу, на котором находится сообщение (`pingRoleId` в
   `config.ts`) — **это предположение**: в ТЗ доступ к кнопке явно назван
   только для роли второго сервера (`1548752262938103899`), для симметрии
   такое же право дано и роли первого сервера (`1552715526671704096`); при
   необходимости легко сузить в `mirror.ts` → `userCanCancel`.
5. `/capt helper-add id:<Discord ID>` / `/capt helper-remove id:<Discord ID>`
   / `/capt helpers` — управление списком помощников, доступно только
   создателю (`CREATOR_ID` в `config.ts`, зафиксирован как `437954847015436288`).
   `/capt status` — сводка за сегодня (создатель + помощники). `/capt
   reset-day` — сброс счётчика за сегодня (только создатель).
6. Бот должен быть приглашён **на оба** сервера (`1546926301699514411` и
   `1509657083010613299`) с правами «View Channel», «Send Messages», «Read
   Message History» в соответствующих каналах — без этого мосты не смогут
   отправлять сообщения.
7. Эмодзи атаки/защиты в сводке (⚔️/🛡️) — заглушка, в ТЗ явно не указаны;
   меняются в `src/captTracker/render.ts` (`ATTACK_EMOJI`/`DEFENSE_EMOJI`),
   можно подставить кастомные эмодзи сервера в виде `<:name:id>`.

Не забудьте перерегистрировать команды (`pnpm --filter @workspace/discord-bot
run deploy-commands`) после обновления — появилась новая команда `/capt`.

## Открытые вопросы / TODO перед продакшеном

- **Список крайм-фракций** — в `lib/log-analyzer/src/factions.ts` сейчас один
  placeholder-id `CRIME`. Замените/дополните реальными id и отображаемыми
  именами фракций, как они называются у вас на сервере — правка только в
  одном месте, парсер и бот ничего не знают о конкретных именах.
- **Постоянство сессий при рестарте бота** — сейчас `session.ts` хранит
  состояние в памяти процесса. Если бот перезапустится посреди визарда,
  активная сессия потеряется (хотя созданный канал останется). Если это
  критично — можно сериализовать `Session` в Postgres (в существующем
  `lib/db`) и восстанавливать на старте по незавершённым каналам.
- **Таймауты шагов** — 15 минут на шаг сбора данных, 5 минут на ввод фамилии
  (`wizard.ts`, `STEP_TIMEOUT_MS`). Поправьте под реальный размер логов.
