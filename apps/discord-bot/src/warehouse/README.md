# warehouse — автопроверка склада и машин фракций

По расписанию (по умолчанию 00:00, 06:00, 12:00, 18:00 МСК, с задержкой ~2 минуты; меняется `/sklad schedule`) бот сам
заходит на gta5rp.com, читает логи фракций за закончившийся период и присылает в
выбранный канал тех, кто взял со склада/из машин слишком много. По фракции, где
подозрительных нет, сообщение не отправляется.

Вид отчёта: заголовок `**Bloods** — подозрительные действия со складом за 12.11.2026 12:00–18:00 МСК`,
дальше блок на каждого игрока:

```
Nick_Name [245351]
🚨 Оружие: со склада 9, вернул 1 → итого 8 (лимит 6)
🚨 Патроны 7.62: набрал из наборов 10420, взял наборов: 52 → итого 10420 (лимит 420)
📤 Взял со склада:
  • Оружие — 9 (AK-47 ×9)
  • Патроны 7.62 — 500
↩️ Вернул на склад:
  • Оружие — 1 (AK-47 ×1)
🎁 Взял наборами:
  • Патроны 7.62 — 10420 (наборов: 52)
  • Броня — 1 (Броня Bloods (М) ×1, наборов: 1)
🔁 Выдач наборов: [FAM] Аптечки ×1, [1 - 7] Броня ×1
```

🚨 — что именно превышено; ниже — полная картина игрока за период: что и сколько взято со склада
и из машин, что возвращено, что получено наборами. «Со склада» и «наборами» всегда разделены.

## Что считается подозрительным

Для каждого игрока и каждого правила (оружие, патроны по калибрам, броня, аптечки, прочее, наборы):

- **Со склада** — сколько взято за период (со склада и из машин вместе). Если включено
  «возвраты вычитаются» (по умолчанию да), то из взятого вычитается то, что игрок
  положил обратно в тот же период. Подозрительно, если итог больше лимита.
- **Всплеск** — сколько штук за короткое окно (например, 4 оружия за 3 минуты), даже
  если общий лимит не превышен.
- **Наборы** («Берет набор [FAM] Аптечки | 60 min: Аптечка EMS x2») считаются по содержимому, по штукам:
  эта строка — 2 аптечки, «7.62mm x210» — 210 патронов 7.62, «Броня Bloods (М) x1» — 1 броня.
  Содержимое **складывается в ту же категорию**, что и склад, и сравнивается с тем же лимитом:
  итого = (взял со склада − вернул) + набрал из наборов. Если 50 наборов по 200 патронов 7.62 — это 10000 патронов,
  и игрок попадает в отчёт с пометкой «набрал из наборов 10000, взял наборов: 50 → итого … (лимит 420)».
  В блоке игрока «взял со склада» и «взял наборами» показаны отдельно, у наборов — сколько наборов взято.
  Отдельно работают правило «Наборы» (сколько раз взят каждый набор) и нарушение перезарядки
  (повторный набор раньше срока из самой строки лога). Строки одного набора подряд (до 10 секунд) — одна выдача.
- Строки «Берет задание на угон …» не учитываются вообще (это не склад).
- Игроки из списка исключений не проверяются.

Пороги по умолчанию (за один период, меняются командами):

| Правило | Лимит за период (склад + наборы) | Всплеск (только склад) |
|---|---|---|
| Оружие | 6 | 4 за 3 мин |
| Патроны 7.62 | 420 | — |
| Патроны 5.56 | 420 | — |
| Патроны 9mm | 400 | — |
| Патроны 12mm | 100 | — |
| Патроны .45 | 300 | — |
| Патроны .50 | 60 | — |
| Патроны (прочие калибры) | 400 | — |
| Броня | 10 | 5 за 3 мин |
| Аптечки и бинты | 30 | — |
| Прочее | 100 | — |
| Наборы | 14 выдач каждого | перезарядка: 2 нарушения |

При обновлении старые сохранённые правила мигрируют сами: один общий лимит патронов заменяется
правилами по калибрам (лимит старого общего правила остаётся у «прочих калибров»).

## Команды `/sklad` (создатель и модераторы, главный сервер)

| Команда | Что делает |
|---|---|
| `/sklad status` | Все настройки и результат последней проверки |
| `/sklad channel` | Канал для отчётов (пока не задан — автопроверка не запускается) |
| `/sklad channel` с полем `id` | Канал можно указать по ID или ссылке — в том числе на другом сервере, где есть бот |
| `/sklad enable` / `/sklad disable` | Включить / выключить автопроверку по расписанию (ручные `run` и `force` работают всегда) |
| `/sklad schedule` | Расписание: `times:0 6 12 18` или `times:02:00 14:30` (МСК); без параметров — показать; `reset:true` — вернуть по умолчанию |
| `/sklad date` | Проверка за дату: `date:12.11.2026 from:18:00 to:00:00` (+ `end_date`, `faction`, `post`). Результат виден только вам, если не `post:true`; точку «проверено до» не трогает |
| `/sklad force` | Принудительная проверка с момента последней проверки до сейчас; `post:false` — показать только вам и не засчитывать |
| `/sklad faction add / remove` | Какие фракции проверять (сейчас Bloods, The Families, Marabunta) |
| `/sklad rule list / set / add / remove / reset` | Пороги: `limit` (склад + наборы), всплеск; свои правила для конкретного предмета или набора |
| `/sklad exclude add / remove / list` | Исключения по ID персонажа |
| `/sklad returns` | Вычитать возвраты или нет |
| `/sklad cooldown` | Проверка перезарядки наборов и сколько нарушений считать подозрительным |
| `/sklad run` | Запустить проверку сейчас (результат показывается только вам; `post:true` — отправить в канал) |

После обновления бота один раз выполните регистрацию команд:
`pnpm --filter @workspace/discord-bot run deploy-commands` (команды появятся не сразу, до часа).

## Проверка за дату (`/sklad date`)

`date` — дата начала (дд.мм.гггг), `from`/`to` — время по МСК (по умолчанию 00:00; если `to` не позже `from`, конец — в следующие сутки,
т. е. `18:00 → 00:00` или целые сутки). Если окно длиннее одних суток, укажите `end_date`. Максимум 72 часа.
Окно режется по границам расписания, каждая часть анализируется по своим порогам. Чем старше дата, тем больше страниц
логов бот листает (от новых к старым); при слишком большой глубине отчёт помечается неполным.

## Принудительная проверка (`/sklad force`)

Бот помнит, до какого момента логи уже проверены (`lastCheckedUntilMs` в `data/warehouse-store.json`,
показывается в `/sklad status` как «Проверено до»). Точка сдвигается после успешной проверки, отчёт
которой дошёл в канал: после автопроверки периода и после `/sklad force` с `post:true`. `/sklad run`
точку не трогает.

- Окно: от «проверено до» (если точки нет — с начала последнего закончившегося периода) до момента команды,
  но не больше 24 часов назад.
- Пороги заданы на один период, поэтому длинное окно режется по границам расписания и каждая
  часть анализируется отдельно. Так же работает и `/sklad run hours:N`.
- Если часть фракций не прочиталась или отчёт не отправился, проверка не засчитывается — повторите команду.
- Периодическая проверка потом всё равно пройдёт период целиком, поэтому те же игроки могут попасть в отчёт повторно.

## Как бот читает сайт

- Фильтр сайта работает по дням, а страница вмещает до 3000 строк (≈7–8 часов),
  поэтому бот запрашивает логи с вчерашнего дня, листает страницы от новых к старым
  (`/logs?act=faction&page=N&from=page_change`) и останавливается, как только дошёл
  до начала нужного периода. Лишние строки отсекаются по времени записи.
- Если на сайте стоит меньше 3000 строк на страницу, бот пробует поднять до максимума;
  не получилось — просто листает больше страниц.
- Если страниц оказалось слишком много (60), отчёт помечается как неполный.
- Если вход не удался, бот присылает владельцу (`WH_OWNER_ID`) в личку скриншот и причину;
  автоповтор — через 20 минут, максимум 3 попытки на период. Вручную: `/sklad run`.

## Установка на VPS (схема деплоя через GitHub, /opt/bots/sklad-bot, пользователь bots)

1. На ПК: скопировать изменения в клон репозитория, выполнить `pnpm install`
   (обновит `pnpm-lock.yaml`), закоммитить всё и отправить на GitHub.
2. На сервере: `sudo -u bots /opt/bots/sklad-bot/deploy/deploy.sh`, затем один раз
   `cd /opt/bots/sklad-bot && sudo -u bots pnpm --filter @workspace/discord-bot run deploy-commands`.
3. Один раз поставить браузер (в общую папку, чтобы видели и ручной запуск, и systemd):
   ```bash
   sudo mkdir -p /opt/bots/browsers && sudo chown bots:bots /opt/bots/browsers
   cd /opt/bots/sklad-bot/apps/discord-bot
   sudo -u bots env PLAYWRIGHT_BROWSERS_PATH=/opt/bots/browsers pnpm exec playwright install chromium
   sudo env PLAYWRIGHT_BROWSERS_PATH=/opt/bots/browsers pnpm exec playwright install-deps chromium
   ```
4. В `/opt/bots/sklad-bot/apps/discord-bot/.env`: `GTA_LOGIN`, `GTA_PASSWORD`,
   `GTA_ADMIN_PASSWORD`, `WH_OWNER_ID`, `PLAYWRIGHT_BROWSERS_PATH=/opt/bots/browsers`.
5. В Discord: `/sklad channel` → выбрать канал, при желании `/sklad status`, `/sklad run`.

Память: на 1 ГБ включите swap (2 ГБ) — Chromium иногда съедает 400–600 МБ.

## Правила безопасности, заложенные в код

- Каждое действие входа пробуется не более 2 раз (защита от блокировки паролем).
- Кнопка «Отключить Google Auth» никогда не нажимается.
- Cloudflare и капчи не обходятся: при проблеме бот присылает скриншот и останавливается.
- Профиль браузера (`data/browser-profile`) содержит сессию — храните как пароль, не копируйте в git.
