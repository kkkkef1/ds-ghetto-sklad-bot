# twink — автопроверка твинков во фракциях

Логика перенесена из расширения «Twink Checker»: для каждого игрока из списка участников фракции бот
нажимает «(ч)», читает окно со списком персонажей, смотрит фракции и проверяет сочетание.
Запрещено: две криминальные, две государственные, криминальная + государственная, криминальная + «особая»
(Medical Services, Weazel News, Мэрия ЛС). Для нарушителей формируются строки
`offwarn ID Твинк КОД | остальные | by <ник>`; в канал они идут по фракциям: название жирным и блок кода (как на скриншоте). Коды фракций — как в расширении (BSG, FAM, MG-13, ESB, LCV…).

## Расписание

- По умолчанию результат должен быть готов в **среду и воскресенье в 09:00 МСК**.
- Проверка долгая, поэтому стартует **за 3 часа** до этого времени (`/twink schedule`).
- Результат публикуется в канал **сразу по готовности** (не дожидаясь 09:00).
- Если бот был выключен в момент старта, проверка запустится при включении (до 6 часов после плановой публикации).

## Что видно в канале

1. При старте — сообщение «Идёт проверка твинков»: фракция, процент, число найденных, примерное время
   окончания. Обновляется раз в минуту (`/twink options progress_sec`, от 10 секунд), только если текст изменился.
2. По окончании это же сообщение превращается в итог, ниже — результат по каждой фракции (блок кода).
3. Ошибки, капча, вопросы про неизвестные фракции — только владельцу (`WH_OWNER_ID`) в личку.

## Общий аккаунт со складом

Склад и твинки используют один аккаунт и один профиль браузера, поэтому на сайт они заходят **по очереди**
(`warehouse/siteLock.ts`): кто уже работает — доделывает до конца, второй ждёт и стартует сразу после него.
Код Google Authenticator запрашивается один раз, куки общие.

Следствие: пока идёт проверка твинков (≈2,5 часа), плановая проверка склада в 06:00 ждёт в очереди. Склад
догоняет её сразу после твинков (ограничение «не старше 3 часов» считается от момента, когда планировщик решил
запуститься, а не от старта браузера).

## Команды `/twink` (как у `/sklad`: создатель и модераторы, главный сервер)

| Команда | Что делает |
|---|---|
| `status` | Настройки, ход проверки, ближайшая публикация, кто сейчас на сайте |
| `channel` | Канал для результатов (по выбору или по ID/ссылке) |
| `enable` / `disable` | Автозапуск по расписанию |
| `schedule` | `days:ср вс`, `time:09:00`, `lead_hours:3`, `reset:true` |
| `force` | Запуск сейчас (`faction:` — только одна фракция) — с кнопками «Подтвердить / Отмена» (видны только вам); результат — в канал |
| `stop` | Остановить и отправить в канал найденное к этому моменту |
| `resume` | Продолжить после капчи / сброса сессии — с того же места |
| `delay` | `delay_ms` (не меньше 4000), `jitter_ms` (случайная добавка), `wait_ms` (ожидание окна) |
| `nick` | Что писать после «by» (по умолчанию «фамилия») |
| `options` | `progress_sec` (период обновления хода, по умолчанию 60), `skip_seen` (не нажимать «(ч)» у уже встреченных ID), `code_block` |
| `link` | Ссылка на список участников фракции; `reset:true` — по умолчанию |
| `map list/add/remove` | Свои фракции: категория и код |

Список проверяемых фракций **общий со складом**: `/sklad faction add|remove` (сейчас Bloods, The Families,
Marabunta). Ссылки по умолчанию лежат в `store.ts` (`DEFAULT_LINKS`) для всех пяти банд; у других фракций
сначала задайте `/twink link`.

## Сбои и перезапуск

- Капча, Cloudflare, сброс сессии, форма входа посреди проверки → проверка **встаёт на паузу**, владельцу
  приходит сообщение. После решения вопроса — `/twink resume`: проверка идёт с того же места.
- Перезапуск бота: состояние (кто проверен, что найдено) лежит в `data/twink-store.json`, после старта бот
  продолжает автоматически. Проверка, стоявшая на паузе, ждёт `/twink resume`.
- Неизвестная фракция у твинка → группа пропускается, владельцу в личку уходит вопрос; ответить нужно
  на него (Reply): `crime TRD`, `state ABC` или `special XYZ`. Потом — `/twink map`.

## Повторы

- Внутри одной проверки одна и та же группа (по набору ID) в результат попадает один раз.
- Между проверками повторы показываются каждый раз, пока вы не выдали offwarn.
- `skip_seen`: после открытия окна «(ч)» все ID из него считаются встреченными; игроки, чей ID в строке списка
  уже встречался, пропускаются без нажатия. Если ID в строке не распознан, бот просто нажимает у всех.

## Что проверить при первом запуске

Страница `mi?act=faction_members` в коде читается теми же селекторами, что в расширении
(`a.link_lock[onclick*="Mi.showMemberChars"]`, `.modal .card`, «ID: N», «Фракция: …»). В начале проверки бот
присылает в личку пример разобранной строки (onclick, ID, текст) — по нему видно, распознан ли ID для `skip_seen`.
В итоге проверки показано «нажато / пропущено повторов»: если пропусков 0, а повторов должно быть много —
ID в строке не распознаётся (пришлите пример строки, поправлю разбор).

## Файлы

| Файл | Что делает |
|---|---|
| `rules.ts` | Категории фракций, коды, допустимые сочетания, формат строк offwarn |
| `store.ts` | Настройки, ссылки, состояние идущей проверки (JSON) |
| `checker.ts` | Сама проверка: браузер, нажатия, пауза, остановка, продолжение, итог |
| `scheduler.ts` | Минутный тик: когда стартовать (среда/воскресенье, за 3 часа) |
| `unknown.ts` | Вопросы владельцу про неизвестные фракции |
| `report.ts` | Тексты: ход проверки, результат |
| `../commands/twink.ts` | Команда `/twink` |
| `../warehouse/siteLock.ts` | Общая очередь на сайт для склада и твинков |
